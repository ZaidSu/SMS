GRANULAR STAFF ACCESS

Give each teacher the access they need — not a one-size-fits-all role.

A principal can start from a permission profile and then customize individual teacher access by module and action.

  • View, Manage, or No Access for supported modules
  • Hidden modules disappear from the teacher navigation
  • Direct-page access checks the same permission
  • Highly sensitive student identifiers are excluded from teacher permissions entirely

SECURITY & ACCESS

Sensitive information should never be ordinary portal data.

SMS separates routine student information from protected identifiers and is structured so production authorization can be enforced at the backend and database level.

Role-Based Access

Different portal roles and page-level access rules keep users focused on what they are responsible for.

Teacher Permissions

School leadership can customize view and manage permissions for individual teachers.

Protected Records

SSN and government identifiers are separated from everyday student profiles and restricted to top-level authorized staff.

Access History

The protected-record workflow is designed to record opens, reveals, and edits for accountability.

Server-Side Ready

The frontend permissions map cleanly to Supabase Auth and row-level security for production enforcement.

Data Separation

School, branch, family, student, academic, billing, and sensitive-record data can be isolated by policy.

The current downloadable project is a frontend workflow demo. Production authentication, database security, storage, and policy enforcement are intentionally planned for the Supabase backend stage rather than being overstated here.
